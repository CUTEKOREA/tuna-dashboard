# P2 클릭 문법 (drill 축소판) — 설계

> 2026-08-17 [CC] · V3 스펙(2026-08-15-metabase-bi-redesign) §4 P2의 분할 스펙.
> 원칙: Metabase «모든 픽셀이 질문의 입구» 번안 — 단, 질의 엔진 없이
> **기존 전역 필터 주입과 정적 JSON 상세를 재사용**하는 축소판.

## 범위 (이번 라운드 — 정찰 실측 반영, 2026-08-17 확정)

정찰 결과 두 가정이 실제 배선과 달랐다: ①market에 카테고리 Bar/Pie가 없어 cross-filter의
카테고리 축은 **범례의 허브 축**이 유일하고, ②unloading에 주차 축 자체가 없다(항차 상세는
연도 키의 검증 이력 98건). 스펙을 실측에 맞춘다.

| 제스처 | 페이지 | 동작 (구현형) |
| --- | --- | --- |
| 범례 클릭 = 허브 cross-filter | market | 범례 허브 클릭 → 시리즈 숨김/복원(취소선+흐림) + URL `?hide=` 직렬화 — 공유 링크가 같은 화면을 연다 |
| 기간 드래그 zoom | market SKJ·YF 차트 | Recharts Brush — 하단 띠 드래그로 구간 확대 |
| 원천 레코드 드릴 | unloading | 연도별 검증 실적 차트의 연도 클릭 → 기존 연도 탭·항차 표(원천 레코드)로 이동. 신규 모달 대신 **기존 표 재사용** — 주차 모달은 주차 데이터가 생기기 전까지 만들지 않는다 (원칙 4 정직) |

## 제외 (명시)

- **SIT/TAK 변수 동적화** — 결정 ②(«전체 기간 기준» 고정 라벨) 유지. 정합성 정책을
  소유자가 재결정하기 전까지 SIT/TAK은 필터와 무관하게 고정.
- **신규 차트형** (Treemap·Waterfall·Gauge) — 적합 데이터 사례가 생길 때 개별 판단.
- 전 페이지 일괄 적용 — 파일럿 판정 후 확산.

## 설계 원칙

1. **위젯별 자체 상태 금지** — cross-filter는 페이지의 기존 필터 상태(단일 출처)를 갱신할 뿐.
   위젯은 지금처럼 필터된 데이터를 받는다.
2. **신설 최소화** — 시리즈 토글은 소비처가 market 하나뿐이라 인라인, 레코드 표시는
   unloading의 기존 연도 탭·항차 표 재사용. 소비처가 2곳 이상 생길 때 프리미티브로 승격.
3. **클릭 가능성은 눈에 보이게** — 클릭 가능한 항목은 hover cursor:pointer + 활성 필터는
   pill로 표시(해제 버튼). 숨은 기능 금지 (SOUL ⑦ 탐색 손잡이).
4. **정직한 상세** — 레코드 시트는 JSON에 실제로 있는 원천 레코드만. 상세가 없는 주차는
   «상세 기록 없음 (사유)» 표기. 생성·보간 금지.

## 수용 기준

- 범례 토글(URL 반영)·Brush 확대·연도 드릴 각 1회 이상 실화면 동작 실증.
- 숨김 허브는 범례 취소선으로 항상 보이고 같은 자리 1클릭 복원.
- npm run verify GREEN. 반증 리뷰(작성자≠검증자) 통과.
