# 「시장 이해 > 참치」 페이지 기획서

작성 2026-08-16 · Claude Code · 대상 저장소 `CUTEKOREA/tuna-dashboard` · 브랜치 `feat/market-understanding-tuna`

## 0. 결론 먼저

**만들 것**: 참치 산업의 밸류체인을 *가르치는* 단일 페이지. 대시보드가 아니라 설명 장치다.

**만들지 않을 것**: 위젯을 더 얹은 대시보드. 이미 있었고 8월 15일에 내렸다.

**핵심 판단**: 「실시간 운영」과 「시장 이해」를 나눈 것은 두 페이지의 *독자가 다르기* 때문이다.
운영 페이지는 구조를 아는 사람이 변화를 감시한다. 이해 페이지는 구조를 모르는 사람이 구조를 얻는다.
같은 숫자라도 전자는 "지금 얼마인가"를, 후자는 "왜 이런 구조인가"를 답해야 한다.

## 1. 왜 기존 `/value-chain`은 이해를 만들지 못했나

8월 15일 커밋 `c492d70`이 `/value-chain`을 메뉴에서 내렸다. 컴포넌트(`TunaDashboard.tsx`, 1,092줄)와
`/api/tuna` 10개 라우트는 복구용으로 살려 뒀고, 렌더 결과는 정적 HTML로 agri_data에 보존됐다.

그 아카이브를 열어 보면 위젯 제목이 111개다. 5-Pillar(원료 수급·가공·물류·판매·ESG)로 나뉘어 있고
각각이 잘 만들어진 분석 위젯이다. 문제는 품질이 아니라 **형식**이었다.

| 관측 | 함의 |
| --- | --- |
| 위젯 111~120개가 5개 탭에 평면 배열 | 어디서부터 읽어야 하는지 알 수 없다. 순서가 없으면 서사가 없고, 서사가 없으면 이해가 안 남는다 |
| 제목이 전부 `[대괄호 태그] + 자극적 문구` | "[기후 충격] 가다랑어 산지가격 폭등" — 결론을 먼저 던진다. 결론은 구조를 아는 사람에게만 의미가 있다 |
| 위젯 하나하나가 독립 | 위젯 A의 숫자가 위젯 B의 숫자를 어떻게 만드는지 연결이 없다. 밸류체인은 연결이 본체다 |
| 5-Pillar가 밸류체인의 실제 단계와 어긋남 | 참치는 **어법에서 이미 두 산업으로 갈린다**. 선망→통조림, 연승→사시미. 이 분기가 5-Pillar에는 없다 |

즉 기존 페이지는 **잘 만든 분석의 창고**였지 **산업의 지도**가 아니었다.

이번 페이지는 지도를 만든다. 창고의 물건(93개 구조화 위젯 데이터)은 지도 위 적절한 자리에 다시 놓는다.

## 2. 이 페이지가 답해야 할 질문

설계 기준을 질문으로 고정한다. 페이지를 다 읽은 사람이 아래에 답할 수 있으면 성공이다.

**구조**
1. 참치 한 마리가 바다에서 식탁까지 오는 경로는 몇 단계이고, 각 단계에 누가 있는가?
2. 왜 "참치 산업"은 하나가 아니라 둘(통조림용·사시미용)인가? 어디서 갈라지는가?
3. 로인(loin)이란 무엇이고 왜 중간재로 따로 거래되는가?

**규모**
4. 세계 참치 어획량은 얼마이고, 어종별·해역별로 어떻게 나뉘는가?
5. 왜 서부·중부태평양(WCPO) 한 해역이 절반 가까이를 차지하는가?
6. 한국은 이 산업의 어디에 있는가?

**돈**
7. 마진은 밸류체인의 어느 지점에서 발생하는가?
8. 방콕 가다랑어 가격은 왜 업계 벤치마크인가? 무엇이 그 가격을 움직이는가?
9. 원어와 조제품의 단가 갭은 무엇을 뜻하는가?

**규칙**
10. 5개 RFMO는 각각 무엇을 관할하고, 쿼터·FAD 금어기·입어료는 사업에 어떻게 작용하는가?
11. IUU·MSC·EU 카드 같은 시장접근 장벽은 실제로 무엇을 막는가?

**자기 위치**
12. 신라교역은 이 사슬의 어디에 있고, 어디가 강하고 어디가 취약한가?

## 3. 페이지 구조 — 7단계 스파인 + 3횡단축

밸류체인은 순서가 있는 사슬이므로 **번호가 정보를 담는다**. 스크롤을 따라 내려가면 참치 한 마리의 경로가 된다.

### 세로축 — 사슬 7단계

| # | 단계 | 답하는 질문 | 핵심 시각화 |
| --- | --- | --- | --- |
| **01** | 자원·해역 | 바다는 누구 관할인가 | 5대 RFMO 관할 구분 + 해역별 어획 비중 |
| **02** | 어획 | 산업이 왜 둘로 갈리는가 | **어법 → 어종 → 최종제품 분기도** (이 페이지의 중심 도해) |
| **03** | 환적·운반 | 보이지 않는 단계에서 무슨 일이 | 운반선 경로, IUU 리스크가 여기 몰리는 이유 |
| **04** | 1차 가공 | 로인이라는 중간재 | 수율 구조(가식부 vs 부산물), 가공허브 3축 |
| **05** | 최종 가공 | 캔·파우치·사시미로 갈림 | 어종별 제품 경로, 단가 계단 |
| **06** | 교역·통관 | HS 코드가 산업을 나눈다 | 원어(0302/0303) vs 조제품(160414) 단가 갭 |
| **07** | 소비 | 누가 먹는가 | 미국·EU·일본·중국 시장 구조 대조 |

### 가로축 — 3개 횡단 레이어

사슬 전체를 관통하므로 단계에 넣지 않고 별도 축으로 세운다.

- **A. 가격 형성** — 방콕 벤치마크가 어떻게 만들어지고 무엇이 움직이는가. 9년 5항구 실측 시계열.
- **B. 규제·지속가능성** — RFMO 조치 → 조업 제약 → 원가. 규제를 비용으로 번역해 보여준다.
- **C. 한국·신라의 위치** — 각 단계마다 "우리는 여기 있다" 마커. 마지막에 종합.

### 화면 상단 — 30초 브리핑

페이지를 처음 여는 사람이 30초 안에 산업의 크기와 모양을 잡는 요약 스트립.
아래로 스크롤하지 않아도 되는 사람을 위한 출구이자, 스크롤할 사람을 위한 지도.

## 5. 구현 배선

### 5.1 사이드바 — 신규 섹션 추가

`lib/dashboard-registry.ts` 한 파일이 사이드바·라우팅·명령팔레트·접근권한을 모두 관장한다. 하드코딩이 아니라 레지스트리다.

| 고칠 곳 | 내용 |
| --- | --- |
| `DashboardSection` 타입 | `'understanding'` 추가 |
| `SECTION_LABELS` | `understanding: '시장 이해'` |
| `SIDEBAR_SECTION_TITLES` | `understanding: '📚 시장 이해'` |
| `SIDEBAR_SECTION_ORDER` | `operation` 다음에 배치 |
| `DASHBOARD_MENU_CONFIGS` | `{ key: 'tuna-industry', title: '참치', section: 'understanding', accent: 'cyan', sidebar: { icon: 'Fish' } }` |
| `SIDEBAR_SECTION_KEYS` | `understanding: ['tuna-industry']` |
| `DASHBOARD_PANEL_ORDER` | `'tuna-industry'` 추가 |

`app/page.tsx`는 SPA 셸이다. `dashboardPanels` 맵에 항목을 넣고 dynamic import를 추가한다.
`heroTeaserPanels`에도 넣을지는 로그인 전 미리보기 정책에 따라 결정한다.

### 5.2 접근 권한

`requiresOperationAccess`를 **붙이지 않는다**. 이 페이지는 사내 대외비가 아니라 산업 일반 지식이고,
운영 데이터(선단·하역·메일)와 성격이 다르다. 다만 로그인 게이트 자체는 셸 공통이라 그대로 적용된다.

### 5.3 데이터 경로 (ADR 0005 준수)

```
agri_data FishStat CSV (175k행)
   ↓ scripts/build_tuna_industry_data.py   ← L-07 스크립트 기반 일괄 변환
public/data/tuna_industry_v1.json          ← 경량 집계본 (<1MB, L-08 준수)
   ↓
lib/data/tuna-industry.ts                  ← 인테이크 모듈. 위젯이 JSON을 보는 유일한 통로
   ↓
components/market-understanding/*.tsx
```

`app/`·`components/`에서 JSON 직접 import는 아키텍처 가드가 막는다. 반드시 `lib/data/` 경유.

### 5.4 텔레메트리 정직 표기 (L-09)

FishStat 집계본은 **정적 파일**이다. `status: 'STATIC'` + `syncDate`로 표기한다.
`LIVE`는 `/api/tuna`의 KCS·WTI처럼 런타임 fetch가 실재하는 위젯에만 붙인다.
아카이브 스냅샷에서 `isLive: true`였던 2건은 정적 재사용 시 `SYNCED`로 강등한다.

## 7. 리스크와 대응

| 리스크 | 실제로 터질 모양 | 대응 |
| --- | --- | --- |
| **또 위젯 창고가 됨** | 설명 없이 차트만 늘어남 | 각 단계는 *서술 먼저, 차트는 근거로*. 차트 없는 단계를 허용한다 |
| **숫자 출처 불명** | "8,346,563톤"이 어디서 왔는지 못 밝힘 | 모든 수치에 출처·기준연도 병기. FishStat는 2022가 최신이므로 그렇게 쓴다 |
